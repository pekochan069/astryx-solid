# Solid 2 migration rules

**Scope.** These rules are based on Solid's official 2.0 beta migration guide. They are migration constraints, not a claim of stable-2.0 compatibility. [Official guide](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md)

## Rules

1. **Props and children:** retain the `props` object; do not destructure or read reactive props at component top level, because beta dev mode warns. Read in JSX/reactive scopes, or use narrowly intentional `untrack`. Function children may receive accessors (not values), notably `Show` and `For keyed={false}`; invoke them. `Index` becomes `For keyed={false}`. [Props diagnostics](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#top-level-reactive-read-in-a-component) · [Control flow](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#list-rendering-index-is-gone-and-for-handles-each-keying-mode)
2. **Events, DOM, refs, and portals:** use camel-case handlers such as `onClick`; `on:`/`oncapture:`, `attr:`, `bool:`, `use:`, `classList`, and `/*@once*/` are removed from the public JSX model. Replace directives with `ref` directive factories (array refs may compose them); use a ref callback for native listener options. Delegation is render-root scoped; nested roots do not cross-delegate, ShadowRoots scope delegation, and a Portal registers an outside-root mount with its owning root so events keep logical-tree bubbling. [DOM/events](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#attributes--events-closer-to-html-and-fewer-namespaces) · [Ref directives](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#directives-use--ref-directive-factories-two-phase-pattern)
3. **Context and lifecycle:** replace `<Context.Provider>` with `<Context value={...}>`. A default-less `createContext<T>()` now has `useContext` type `T` and throws `ContextNotFoundError` if unprovided; use an explicit default only when fallback behavior is intended. Replace `onMount` with `onSettled`, which may return cleanup. Effects are compute/apply: put side effects and cleanup return in apply; writes inside reactive owned scopes throw in dev unless the narrow `ownedWrite: true` exception applies. [Context](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#context) · [Effects/lifecycle](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#effects-lifecycle-and-cleanup)
4. **Scheduling/compiler behavior:** writes batch to a microtask, so reads immediately after a setter still see the prior value; use `flush()` only at necessary synchronous boundaries (especially tests/imperative interop). Treat dev diagnostics as migration failures: remove top-level reactive reads and reactive write-backs; derive with `createMemo` instead. Set web TypeScript JSX ownership to `jsx: "preserve"` and `jsxImportSource: "@solidjs/web"`; `solid-js` no longer owns JSX runtime/types. [Batching](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#batching--reads-values-update-after-flush) · [JSX ownership](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#typescript-jsx-solid-js--renderer-package)
5. **SSR and hydration:** migrate DOM imports from `solid-js/web` to `@solidjs/web`, including `hydrate`. The supplied official guide does not define a broader SSR/hydration compatibility guarantee; it explicitly directs readers to separate Reveal SSR caveats. Do not infer stable SSR parity from this beta guide—validate each SSR/hydration entry point and loading/reveal behavior in the target app. [Imports](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#imports-where-things-live-now) · [Reveal note](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#coordinating-loading-boundaries-suspenselist--reveal)
6. **Version policy (recommendation):** keep this migration on an exact, explicitly recorded Solid 2 beta version across `solid-js` and all `@solidjs/*` renderer packages; do not use floating ranges or independently upgrade packages. Upgrade only as a deliberate, tested compatibility change, then pin the selected beta again. This containment is appropriate because the official document labels itself a beta guide and records behavior already changed between earlier betas (for example `Reveal`'s `together` prop became `order="together"`). [Beta guide](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md) · [Earlier-beta change](https://github.com/solidjs/solid/blob/next/documentation/solid-2.0/MIGRATION.md#coordinating-loading-boundaries-suspenselist--reveal)
